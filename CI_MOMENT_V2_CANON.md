# Ci Moment V2 Canon — Legend ci Artifact Machine

Status: CI-MODEL / product canon
Branch: `next/from-working-mvp`
Base: restored working MVP baseline

## 1. Core Product Thesis

Ci Moment V2 is not a generic decision app. It is a zero-auth digital artifact machine that mints a deterministic personal pass.

The user does not buy advice. The user claims a durable symbolic artifact: a generated document that records a moment, a relation, and a cipher.

Canonical framing:

- Product: digital artifact / pass / key.
- Surface: single-page vending machine.
- Output: banknote-like official artifact with a deterministic cipher.
- Meaning layer: Legend ci constitutional fragment unlocked by the cipher.
- Price anchor: one coffee / $5 standard pass.
- Gift mode: same $5 pass can be generated for another person.

## 2. Correct Positioning

Use:

- Claim the Pass
- Secure the Key
- Open the Seal
- Reveal the Artifact
- Verify Artifact
- Legend ci Fragment

Avoid in primary UI:

- Buy
- Pay
- Donate
- Prediction
- Fortune telling
- Horoscope
- Medical/legal/financial advice

The product should feel like an institutional digital relic, not a mystical toy.

## 3. Visual Canon

Target aesthetic:

- American retro-professional
- 1970s industrial cyber-archive
- old paper / transit pass / banknote / hall pass / archive certificate
- guilloche borders
- serial numbers
- official stamps
- Courier Prime / monospace typography
- restrained palette: off-black terminal + aged paper

Artifact should evoke:

- 100-dollar-bill structural seriousness without copying protected currency design
- constitution-like permanence without claiming governmental authority
- official document feeling without impersonating a real institution

Required legal-safe distinction:

The artifact may be inspired by banknotes and constitutional documents, but must not imitate real US currency, official seals, government layouts, or official legal instruments.

## 4. User Flow — The 3-Step Spark

### Step 1 — Trigger

User enters:

- sender name or alias
- receiver name or alias
- optional context phrase

No account. No password. No email required.

### Step 2 — Claim

User clicks:

- `Secure the Pass — $5`

Gumroad overlay handles payment.

### Step 3 — Revelation

After payment or pass claim:

- user lands on `/open/[saleId]` or equivalent key URL
- sealed envelope appears
- click reveals artifact
- artifact displays cipher and Legend ci fragment
- user can share the sealed key or save artifact image

## 5. Cipher Model

The cipher is the bearer identity of the artifact.

Canonical shape:

```text
[element]-[celestial]-[logic]-[serial]
```

Internal indices:

```text
element:   0..3
celestial: 0..8
logic:     0..23
```

The cipher is generated by a deterministic pure function from normalized inputs:

```text
senderName + receiverName + contextHash + optional timestamp/sale seed
```

The cipher unlocks a stable Legend ci fragment. Same cipher must always return the same legend.

## 6. Legend ci Constitution Layer

The artifact is not the final object. It is the key.

`Verify Artifact` or `/verify` allows a user to re-enter the cipher and retrieve the same Legend ci fragment later.

The Legend fragment is composed from:

- Element text: base system state
- Celestial text: environmental influence
- Logic text: action vector

Rule:

`getLegendByCipher(cipher)` must be pure and deterministic.

## 7. Data Policy

Preferred product principle:

```text
Input -> Output -> Forget
```

But implementation must be honest.

If Gumroad webhooks or Supabase/Prisma store `saleId`, `senderName`, `receiverName`, and `cipher`, then the system is not strictly zero-data. It is minimal-data.

Therefore define two modes:

### Mode A — Zero-Data Local Artifact

- no server persistence of names
- cipher and artifact generated client-side or from non-personal sale key
- user owns screenshot / local artifact
- verification works only from cipher, not stored identity

### Mode B — Minimal-Data Gift Artifact

- server stores only what is necessary for recipient link
- fields: `saleId`, `senderName`, `receiverName`, `cipher`, `isSealed`, `createdAt`
- no accounts, no profile, no tracking history
- visible privacy statement required

For V2 MVP, use Mode B only if gift/open link is required.

## 8. Payment Canon

Payment processor: Gumroad overlay.

Primary product:

- standard pass: $5
- gift pass: $5

Do not describe payment as tax avoidance or legal invisibility. Gumroad is the merchant/payment processor, but revenue, tax, platform terms, and jurisdictional obligations still require normal compliance.

Safe framing:

- digital artifact purchase
- support pass
- paid digital download/access
- Gumroad processes checkout

Risky framing to avoid:

- invisible transaction
- avoid taxes
- not legally payment
- donation masking a purchase

## 9. Database Canon

If using server persistence, simplify to one model:

```prisma
model Artifact {
  id           String   @id @default(cuid())
  saleId       String   @unique
  senderName   String
  receiverName String
  cipher       String
  isSealed     Boolean  @default(true)
  createdAt    DateTime @default(now())
}
```

No user model. No profile. No auth tables. No unnecessary decision history.
